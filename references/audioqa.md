# Audio QA for long and mixed-language recordings

Install the audio QA extras and FFmpeg with FFprobe. The scan can run entirely on the workstation.

~~~sh
python -m pip install -r requirements-audioqa.txt
python -m scripts.setup_lexicon --nofa
python -m scripts.setup_multilingual
python -c "from faster_whisper.utils import download_model; download_model('large-v3', output_dir='models/asr/whisper-large-v3')"
python -m audioqa scan --audio input.mp3 --asr faster=models/asr/whisper-large-v3 --deep --high-recall --local-only --out runs/scan
~~~

Use a local multilingual CTranslate2 model with `--asr faster=DIR`. A smaller model works for a faster first pass. Repeat the flag to compare engines. Installed OpenAI Whisper can use `--asr openai=CHECKPOINT.pt`. For NB Whisper and NB Whisper Verbatim use `--asr nb=DIR` and `--asr nb-verbatim=DIR` with local CTranslate2 exports or install PyTorch and Transformers for original checkpoints. `nb-whisperx` uses the local recognizer path. Export aligned results from the NB WhisperX toolkit or supply NoFA for the phone boundaries. Word timestamps from Whisper estimate the realization and describe what the recognizer heard. The default pass detects window language. Norwegian-specific ASR is directed to likely Norwegian windows.

Supported inputs include WAV, MP3, FLAC, M4A, MP4 and a local directory. For Google Drive use a synced path or `--audio rclone:REMOTE:path/to/file.mp3` with a configured authorized rclone remote. `--reference` accepts TXT, SRT and VTT. For paths with spaces, quote the argument. Originals are opened for reading. The run stores a losslessly decoded float audio cache, an immutable input digest, a manifest and per-window checkpoints. Keep the same input path, model and scan settings with `--resume`. CPU is the default. Use `--gpu` on a configured CUDA/CTranslate2 installation and adjust `--workers` according to memory and model throughput.

Without a manuscript, the output includes timed reverse transcripts for inspection. Use `--nofa-command /path/to/mfa_align` for bounded Norwegian alignment runs. `--max-alignments` covers the configured number of eligible regions. For Ukrainian or English alignment specify the available MFA executable and a JSON map in `--mfa-models`, for example `{"uk-UA":["path/to/ukrainian_mfa.dict","path/to/ukrainian_mfa.zip"]}`. Use the locally installed model's matching dictionary. These aligners condition on expected phones and operate separately from independently observed phones.

The scan runs signal detectors across the whole decoded track, including outside speech. The report distinguishes sample-clock timing from estimated speech timing. `--high-recall` relaxes screening, `--high-precision` tightens it, and `--artifact-only` and `--pronunciation-only` isolate analysis. `--dry-run` avoids decoding and requests. For an existing report run `python -m audioqa review --report runs/scan/reports/defects.json`. Open `review/index.html` with the `clips/` directory next to it. The page plays the event and context, displays waveform and spectrogram, and saves decisions locally. Export decisions as JSON to reuse them from the CLI.

The report contains JSON and CSV events, defect-marker SRT, evidence JSON and WAV/PNG extracts. Very long candidate intervals include a preview of their first 24 seconds, with the full interval retained in the report. Listen at the recorded timestamps for a longer review. `candidate_listening_minutes` is the union of non-info review clips. The relative detector fits thresholds to the recording's candidate distribution. Use a separately confirmed profile built with `voice-profile --reports CLEAN_REPORTS --metadata META --out profile.json` for comparing dynamics, pitch, noise, MFCC, pace and pauses for a single voice. Supply the review evidence and voice ID in the profile and source metadata.

## Phonetic and multilingual evidence

Use explicit language annotations on spoken spans, for example `«[[nb-NO|å gi opp]]»`, or pass `--language-spans` with spoken-text offsets and locale. The original script stays available and the markup is absent from synthesis text. Mark examples and short ambiguous words explicitly. The route preserves context, intentional switching, expected locale and separate unknown or tentative audio language fields. Text LID and ASR LID do not describe the accent of an individual word.

- Bokmål uses NB Uttale, including stress and lexical tones. English US uses CMUdict, including primary and secondary stress on its vowel phones. English UK uses the British MFA dictionary and flags unavailable stress. Ukrainian uses the Ukrainian MFA phone dictionary and can use a locally authorized UTF-8 accent list with combining acute marks through `--ukrainian-stress`. For normative or uncertain forms consult the ULIF dictionary and a qualified reviewer. [Ukrainian phonetic description](https://doi.org/10.1017/S0025100316000372) · [ULIF dictionary](https://services.ulif.org.ua/expl/) · [CMUdict](https://github.com/cmusphinx/cmudict)
- Supply independent phone observations as a JSON list with `start`, `end`, `model`, `alphabet` and an array of `phones`. Use `IPA`, `MFA_IPA`, `NoFAbet` or `CMU` matching the target. Include reviewed `locale_validation_evidence` before comparing foreign phonetic patterns and optionally include observed stress indices or a lexical toneme from the validated system. Scores are edit similarities, not calibrated probabilities. Dictionaries' language-specific inventories are retained, and IPA only normalizes formatting for comparison. Unsupported observations remain review candidates.
- Plan mixed text with `python -m audioqa plan-mixed --text examples/mixed_input.txt --strategy hybrid --out runs/mixed`. Available variants are `single`, `blocks`, `language` and `hybrid`. Mixed segments omit a global language code. Single-locale segments use documented codes. A live audition needs a voice, `--live`, `--max-api-budget` in locally reserved characters and `--max-regenerations`. Compare transitions with the same voice and independently reviewed audio before selecting a strategy. Use the [review record schema](correction_record.md) to learn locale-scoped fixes.

## Optional cloud reviewers

Scribe audio uploads need `--scribe --allow-cloud --max-cloud-seconds N` and an ElevenLabs key. Gemini needs `--audio-reviewer MODEL --allow-cloud --max-review-calls N` and `GEMINI_API_KEY`. Only Gemini review clips with context and selected supporting evidence are sent. Save the approximate model findings as supplementary evidence and use the local signal, ASR or alignment to refine timing. A failed request is marked before upload, so resuming a run avoids an ambiguous or duplicate paid call. Provider integrations are optional. [ElevenLabs transcript API](https://elevenlabs.io/docs/api-reference/speech-to-text/convert) · [Gemini audio input](https://ai.google.dev/gemini-api/docs/audio)

## Repair and validate

~~~sh
python -m audioqa repair --audio input.mp3 --report runs/scan/reports/defects.json --decisions review-decisions.json --approved-only --video-locked --out runs/repair
python -m audioqa validate --audio runs/repair/repaired.wav --out runs/validation
python -m audioqa benchmark --report runs/scan/reports/defects.json --annotations reviewed-intervals.json --out runs/benchmark.json
~~~

Digital clicks can be interpolated over a short bounded sample interval. The local detector checks the result and the assembled candidate gets a complete global digital rescan. Uncertain clicks, clipping and longer holes go to review. Use `--automatic-digital` only when the run is authorized to apply this bounded method. `--human-review` leaves FULL AUTO in report mode. TTS actions use an authoritative script, the original voice and model from generation metadata, and a positive budget. Candidate WAVs remain pending human review. For a reviewed replacement, include a `VERIFIED` decision dated by the reviewer, `--replacement-manifest` mapping event IDs to replacement WAV paths, and a local `--whisper-model` for the regression check. The repair path tests signal continuity, independent ASR disagreements and total timing. For interactive candidate generation, run `review --serve` with original generation metadata and explicit limits, and use the localhost URL. It listens on loopback and only accepts requests from the opened review session.

FREE_TIMING is the default. VIDEO_LOCKED requires the original decoded sample count, guards cut energy and caps tempo changes at 8%. SUBTITLE_SYNC accepts a source subtitle file, computes cue offsets and exports an updated SRT. Confirmed examples and explicit false-positive labels are separate from unreviewed candidates in the local artifact memory. Original media is never edited in place. Benchmark annotations must have independent start, end and category fields. No manual annotations means no precision, recall, F1 or identified error rate.

## Research and limitations

The local baseline uses explicit signal measurements and robust within-voice feature distances. An isolated high-frequency event can be a natural fricative, a routine breath or a digital artifact. NoFA and MFA do not identify spoken phones. The optional audio reviewer and independent phone inputs add evidence without allocating a numerical calibrated probability. Feature-profile comparisons are exploratory with sparse clean data. Neural embedding candidates such as wav2vec 2.0, HuBERT, WavLM and BEATs require a benchmark with voice-, codec- and locale-matched examples before they can replace these detectors. LOF and Isolation Forest need representative normal examples and threshold validation. No neural anomaly model, calibrated codec classifier, context-independent accent score or automatic syllable-stutter verdict is shipped. Jitter and shimmer require stable voiced portions and are not currently used to classify this material.
